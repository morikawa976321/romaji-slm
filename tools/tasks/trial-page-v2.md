# 依頼: 体験版ページを「一本道」に作り直す（V0 → V0.2）

最初に CLAUDE.md、docs/TRIAL.md、trial/（server.py・engine.py・summary.py・static/*・configs.json・bench_sentences.jsonl・run.ps1・README-trial.md）、tests/test_trial_server.py、docs/decisions.md（D2・D7〜D10）、docs/DESIGN.md（要件表。変えない）を読むこと。文書・コメント・コミットメッセージは日本語。

## 背景

V0（PR #6）は 3 タブ（比べる／打ってみる／まとめ）で、開発機では本物のエンジンで動いた。相談役（astra）のレビュー（2026-10-15、docs/decisions.md D10）で、本人の1回の着席を短くするには**「何をすれば終わるかを本人が考える時間」を削る**べきで、3 タブの自由探索を「少数の比較 → 選んだ組合せを体感 → 結果をコピー」の一本道にするのが妥当、と指摘された。合わせて次の事実の不備も見つかった:

- `trial/bench_sentences.jsonl` の 20 文はすべて `,.?!` を含む。コアは句読点を打った入力では自動挿入しないので、**句読点 B を試せる例文が無く、B の計測値も自動挿入が働く場合の値ではない**。
- 比較で感じる待ち時間は 2〜3 設定の逐次実行の合計で、単独設定の速さではない。
- `accurate` と `en_registered` は同じ設定（重複計測）。`fast` は k=3 だが、docs の xsmall の精度は k=5 の値（親が configs.json の fast を k=5 に直した）。
- 投票の集計は設定の採用への同意ではない。「全部問題ない」は無差別、「一番いい」は相対評価。結果ブロックの冒頭に**本人の明示回答**が要る。
- `record()` が保存失敗を飲んで正常終了扱いにする。過去の起動の記録もまとめに混ざる。

## 作るもの（`trial/` の作り直し。サーバの API は必要なら変えてよい。`core/`・`eval/`・`pyproject.toml`・`uv.lock` は変えない）

### 画面: 1 ページのステップ式（戻るボタンあり）。クリックだけで最後まで進める

**ステップ 0 準備**: 起動直後に既定設定で 1 文を空回しし「準備できました」と出す（既に engine.preload が空回しする。表示だけ）。

**ステップ 1 句読点（A/B）**: 例文 3 つを順に出す。例文は**句読点を打たない**入力で、(i) 完結した文（例 `kyouhaosokunarisoudakarasakinitabeteoite`）、(ii) 質問（例 `ashitanokaiginanjikaradakke`）、(iii) メモや途中の節（例 `kaimonogyuunyuutamagopan`、`raishuunogetsuyoubinihaishanoyoyaku`）。各例は入力済みで表示し、本人は「この例を変換」を押すだけ。結果は `punct_a`（small, punct=ja, en_case=typed）と `punct_b`（small, punct=insert, en_case=typed）を A/B のブラインドで並べ、「こちらがいい」（各カード）／「どちらも問題ない」／「どちらも使えない」。3 例が終わったら**カード 1**:
> 普段は、句読点を自分で打つ形と、自動で補う形のどちらにしますか？
> 選択肢: 自分で打つ（A）／自動で補う（B）／どちらも問題ない／まだ決められない
> 「どちらも問題なければ、意図しない追加を避けるため今回は自分で打つ設定（A）にします。自動で補う設定も後から選べます。」（この同点時の割当ては AI の暫定運用であって本人の好みではない。結果ブロックでそう区別する）

**ステップ 2 英字の表記**: 例文 3 つ（(i) 登録語 `githubnipushshiteoite.`／`pythonnoba-jonwo3.12niageta.`、(ii) 辞書に無い短い英字列 `jrnoekimadearuku.`／`scc-0210womitsukete.`、(iii) 識別子 `claude.mdnikisokuwotsuikashite.`）。`en_typed` / `en_registered` / `en_auto`（いずれも small, punct=auto）を A/B/C で並べ、同じボタン。**親が実コアで 3 方式の出力に差が出る例を確かめてから採用する**ので、例文は `trial/examples.json` に置き、親が差し替えられるようにする。終わったら**カード 2**:
> 英字の大文字・小文字は、普段どこまで自動で整えますか？
> 選択肢: 打ったまま／登録語だけ整える／短い未知語も整える（自動）／どれも問題ない／まだ決められない
> 「どれも問題なければ今回は打ったままにします。」

**ステップ 3 体感**: カード 1・2 の選択（未決・問題なしは暫定値）を組み合わせた設定（small）で、用意した 20〜30 字の例を 1 回、その続きとして左文脈ありでもう 1 回、本人は「変換」を押すだけ。任意で「自分の文を試す」入力欄（Enter で変換、確定欄に追記、左文脈 60 字）。待ちが気になれば「速度優先（xsmall）でも同じ文を試す」ボタン。終わったら**カード 3**:
> 今試した変換を、自分の文章でも使ってみたいですか？
> 選択肢: 使ってみたい／今は使いたくない／まだ判断できない
> 「IME 化は別途判断します。」

**ステップ 4 計測とコピー**: 自動で短い計測を走らせる（本人の操作は不要。進捗を出す）: 最終的に選んだ組合せで 6 文（うち 2 文は句読点なし＝B なら挿入が働く）、small と xsmall を同じ 3 文で比較。各文の ms・最大・1 秒超の件数を出す（少数なので p95 は出さない）。終わったら結果ブロックと「結果をコピー」。

- 比較のステップでは ms を表示しない（表記の好みに速度を混ぜない）。結果ブロックには残す。
- 推論の開始は常に本人のボタン操作（ライブ変換はしない）。
- 選択・回答は押した時点で保存し、**保存の完了を待ってから次へ進む**（失敗したら再試行し、ブラウザ側（localStorage）にも保持して結果ブロックに出す）。
- 起動ごとにセッション id を振り、結果ブロックは今回のセッションだけを集計する（過去の回数だけ添える）。再読込しても回答済みの位置から続けられる。

### 起動

- サーバは起動時に実際の URL を**標準出力に 1 行**で出し（flush）、`trial/out/url.txt` にも書く。`trial/run.ps1` は親が直す（サーバの標準出力を黒いウィンドウに出す）。
- `webbrowser.open()` の失敗を扱い、黒いウィンドウの URL を開けばよい旨を出す。

### テスト・文書

- `tests/test_trial_server.py` を新しい API に合わせて書き直す（MockEngine。保存の完了待ち・セッション分離・結果ブロックの冒頭の回答・計測の形）。`uv run pytest` 全部通ること（torch 無しでも trial のテストが動くこと）。
- `docs/TRIAL.md` を書き直す（**「コアが句読点・英字の設定を受け付けない」という古い制限は消す**。親が core 側に `punct` と `en_case` を実装済み）。`trial/README-trial.md` の本人向け手順は「解凍 → run.cmd → 画面の順に押す → 最後に『結果をコピー』を押して貼る」の 4 手だけにする。
- `tools/pack-trial.ps1` は新しいファイル構成に追随させる。

## 作業の規則

- ブランチ `claude/trial-page-v2` で作業し、コミットはパス指定（`git add <path>` → `git commit -- <path>`）。完了したら push し、main への PR を作る。**push 先はこのブランチだけ。**
- **`core/`・`eval/`・`pyproject.toml`・`uv.lock`・`trial/run.cmd`・`trial/run.ps1` は変えない**（run.ps1 は親が直す。要望は PR 本文に）。
- 認証情報・個人情報を書かない。外部サービスへの書き込みは PR の作成だけ。
- この環境からは huggingface.co と download.pytorch.org に届かない。torch 無しで MockEngine とテストが動くこと。
- 最終報告（PR 本文）: 画面の流れ（各ステップの操作数）、API の変更点、動作確認の方法と結果（Playwright 等で通し操作をしたなら操作数と所要）、親が後でやること（例文の差し替え・実コアでの通し・pack・run.ps1）、未解決の論点。
