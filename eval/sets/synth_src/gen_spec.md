# 評価用の日本語文を書く依頼（romaji-slm）

ローマ字一括変換器 romaji-slm の評価セットを作る。あなたは「正解の出力文」と「その読み」を書く。打鍵（ローマ字）は後で機械的に作るので書かなくてよい。

## 本人（使う人）の文体（実際の入力から）
- AI のコーディングエージェントへの指示や報告: 「githubにprを出してマージして」「supabaseでテーブルを新規作成し」「できたのだが、2回enterキーを押さないと入らない時があったり」「この問題は一旦忘れていい」「トークン余っているし」
- 作業・設計の相談: 「誤字脱字を少しずつ直していく仕組みが欲しいのだが、どういう仕組みを作ったらいいだろう？」「私が手動で直した部分を辞書に追加するとか？」
- 電子工作: 「サーボモーター」「電圧」「圧力」
- 創作・文語: 「昔々竹取の翁というものありけり」「白い山、黒い海」
- 文節ごとに区切って確定することも多い: 「大量の」「入力と」「出力の」「組を用意し、」
- 英単語はローマ字ではなく英字の綴りのまま、**小文字で**打つ（github, pr, supabase, docker, api, readme, python, ctrl, enter, text, editor, microphone）。出力文でも英単語は打ったとおりの小文字で書く（本人の設定「英字は打ったまま」）。
- 口調は常体（だ・である、〜して、〜かも、〜だろうか）が多く、丁寧語も混じる。

## 書くもの
指定された 2 つの題材について、それぞれ **100 件**（計 200 件）。1 行 1 件の JSON（JSONL）で、指定のパスに Write ツールで書く。

```
{"category": "<題材の英字名>", "output": "正解の出力文", "reading": "読み（ひらがな。英単語・数字・記号は出力と同じ文字のまま）", "kind": "sentence または fragment"}
```

- output: 本人が実際に打ちそうな自然な日本語。長さは 5〜50 字でばらつかせる。完結した文（kind=sentence）は文末に「。」「？」などを付け、読点も自然に入れる。文節の断片（kind=fragment、各題材の 2 割ほど）は句読点を付けない（文の途中を想定）。
- reading: output をそのまま読み下したひらがな。漢字だけをひらがなにし、ひらがな・カタカナ語（カタカナはひらがなにする）・英単語・数字・記号・句読点は output と同じ位置にそのまま残す。例: output「githubにprを出して、レビューを受けた後にマージして。」→ reading「githubにprをだして、れびゅーをうけたあとにまーじして。」。数字は読みにしない（「10時」→「10じ」）。
- 読みが 2 通りある語（「今日」きょう/こんにち 等）は、文脈で自然な方。固有名詞や難読語は、読みに自信がないなら使わない。
- 同じ文の言い換えを並べない。題材の中で語彙・構文をばらつかせる。漢字の同音異義語（電圧/田圧、移行/以降、期待/機体 など）を自然に含む文を混ぜると良い評価になる。

## 禁止
- 書いてよいのは指定のパス 1 つだけ。他のファイルを作らない・変えない。
- 実在の個人の名前、個人情報、認証情報を書かない。

## 終わり方
書いたら件数（題材ごと、sentence/fragment 別）だけを報告して終える。
