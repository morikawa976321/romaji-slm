# 設計

ローマ字（小文字英字・数字・記号）の打鍵列を、ローカルの小型言語モデルで日本語に変換する。

## 要件（2026-10-11 本人確定）

| 項目 | 決定 |
|---|---|
| 入力 | 英語入力モードで打てる文字のうち、大文字英字を除くもの（小文字英字・数字・記号） |
| ローマ字 | 標準ローマ字。打鍵ミス・脱字はモデルが吸収する。母音省略などの略記は扱わない |
| 変換の範囲 | ローマ字→かなも含めてモデルが担う |
| 英単語・記号 | 英語のまま残すか、句読点・長音・全角半角をどうするかはモデルが文脈で決める |
| 変換の契機 | キーを押したときだけ（打鍵ごとのライブ変換はしない） |
| 1回の長さ | 1単語〜1文。ツール側で「推奨する長さの範囲」を設けてよい |
| 出力 | 1候補のみ。誤りが多発したら訂正手段を考える |
| 左文脈 | 速度に余裕があれば渡す。遅くなりすぎるなら渡さない |
| 個人化 | 初版ではしない。誤りが多ければ追加学習を検討する |
| 速度 | ThinkPad P14s Gen 6（Core Ultra 7 255H、内蔵GPUのみ、32GB）で、20〜30字の文を1秒以内 |
| 学習機 | デスクトップ（RTX 5060 Ti 16GB） |
| 用途 | チャット、AIへの指示・技術文、論文・レポート、メモ・日記のすべて |
| 土台 | 既存モデルの流用・微調整でよい |
| 配布 | OSS 公開の可能性あり。公開できるライセンスの素材だけ使う |
| 採用基準 | 明文化しない。実用して体感で決める |
| 作る順序 | 変換コア（ライブラリ＋CLI）を先に作る。IME 化（Windows TSF / fcitx5）は後で決める |

ThinkPad は 2028-01 頃まで Windows、その後 Debian 13 に移る予定。コアは OS に依存させない。

## 先行例（2026-10-11 調査）

| 名前 | 入力 | 規模・形式 | ライセンス | 要点 |
|---|---|---|---|---|
| zenz（`Miwa-Keita/zenz-v3.1-small` 等） | カタカナ読み | GPT-2 文字単位。small 90.5M / xsmall 22.5M。GGUF あり（v3.2-small Q5_K_M 73.9MB） | 重み CC BY-SA 4.0（v3.2 GGUF のメタは apache-2.0 と表示、食い違いは未解決） | azooKey の変換モデル。v3 系は `<左文脈><入力><出力>` で左文脈を取る。ローマ字は受けない |
| zenz-v2.5 データセット（`Miwa-Keita/zenz-v2.5-dataset`） | — | 約1.9億ペア（カタカナ読み・出力・左文脈） | 大半 CC BY-SA 4.0、llm-jp-corpus v3 の CC 部分は ODC-BY | 日本語 Wikipedia（2024-02）と llm-jp-corpus v3 由来 |
| romaji2ja（`limoXD/romaji2ja`） | ローマ字直接 | Qwen3 系 約0.3B、fp32 safetensors | 重み CC BY-SA 4.0、コード MIT | 要件にもっとも近い。打鍵ミス対応。正規化後 98.09%（771/786、自作ゲート）、未正規化 約93.4%。英単語・記号の扱いと推論速度の記載なし |
| Karukan（`togatoga/karukan`） | ローマ字→ひらがなは別段（規則） | llama.cpp で GPT-2/Qwen3 系 | MIT OR Apache-2.0 | fcitx5 / macOS の IME。Debian 移行後の組み込み先の参考 |
| AJIMEE-Bench（`ensan-hcl/AJIMEE-Bench`） | カタカナ読み | 200件（左文脈あり100・なし100）JSON | データ CC BY-SA 3.0、コード CC0 | 変換評価の既存ベンチ |

速度の実測値は、255H 上で 100M 級のモデルを動かした公開値が見つからない。ThinkPad で `llama-bench` を回して測る必要がある。参考値として、zenz-v1 は M2 Pro の Mac mini で 1問あたり 0.06 秒（Zenn `azookey/articles/ea15bacf81521e`）。

## 方式の候補

1. **規則でカタカナに変換し、zenz に渡す** — 最速で作れるが、要件を満たさない。英単語はカタカナ化された時点で判別できず、打鍵ミスも規則で落ちる。比較用のベースラインとしてだけ使う。
2. **romaji2ja をそのまま使う** — 要件に最も近い既製品。0.3B で、ThinkPad で1秒に収まるかと、英単語・記号の扱いが未確認。
3. **zenz を、ローマ字を直接受けるように微調整する（本命案）** — 文字単位 GPT-2 なので、ラテン文字を入力側に並べても語彙を拡張せずに済む見込み。90M と 22.5M の2サイズがあり、速度の余裕を左文脈に回せる。学習データは「日本語文 → 読み → ローマ字＋打鍵ミスのノイズ」を規則で生成し、英単語の区間は小文字化した原綴りを入力、元の表記を出力とする。重みは CC BY-SA 4.0 で公開できる。

## 進め方

1. **ベースラインの評価**（ローカル）: 方式1と方式2を、本人の文章と AJIMEE-Bench で試す。方式2で十分なら、ここで終わってよい。
2. **ThinkPad での速度測定**: zenz-v3.x-small/xsmall と romaji2ja を GGUF にして `llama-bench`（CPU / Vulkan / SYCL）で測る。
3. **方式3の部品**（クラウドセッションに並行で出せる）:
   - 学習データ生成パイプライン（読み付与・ローマ字化・打鍵ミス注入・英字区間と記号の扱い）
   - 評価の仕組み（文字誤り率・完全一致・AJIMEE-Bench のローマ字版）
   - 微調整スクリプト（CPU で小さい設定が通るところまで。本学習は 5060 Ti）
   - 推論 CLI（GGUF 変換、llama.cpp で `ローマ字 → 日本語`）
4. **本学習と実用試験**（ローカル）

## 未確認の論点

- zenz の文字単位トークナイザ（ku-nlp/gpt2-small-japanese-char 系）がラテン小文字・記号を単独トークンとして持つか
- 日本語 Wikipedia 由来の学習で、公開する重みに CC BY-SA が及ぶか（CC 自身は保守的な読みを示しつつ、法的結論は出ていない）。CC BY-SA 4.0 で出す前提なら問題にならない
- 読み付与の精度（MeCab＋UniDic / Sudachi / pyopenjtalk）。読みの誤りはそのまま学習データの誤りになる
