本人の回答の要旨: 句読点・?!・鍵かっこ・改行の自動挿入が理想、難しければ自分で打って全角半角だけ自動でもよい／大文字小文字はどちらでもよい／ライセンスはこれで構わない（公開時に詳細を考える）／azooKey への切り替えは必要になってから考える。

これを受けた進め方（AI の判断）: 変換コアは「記号は打つ、種類と幅を決める」で先に完成させる。自動挿入（句読点・?!・鍵かっこ・改行）は、コアと混ぜずに独立の実験として可否を測り、別部品として後から足す。英語の表記は辞書の登録表記があればそれ、無ければ打ったまま。

## 診断（3者一致）

- 方式1（規則でローマ字→カタカナ→元の zenz）の失敗は、ほぼ前段（ローマ字→読み）の英単語と打鍵ミスだけ。zenz の変換そのものは AJIMEE で 87%。
- 微調整はその前段を直すために、強い後段（かな漢字変換の知識）を削った（v1: AJIMEE 87%→28.5%、v2: 正解の読みを与えても 87%→72.5%）。方向が逆。
- 「視線計測→支線系側」「遅く→お酒」「ユウイサ→優位性」は、出力を読みに縛る制約が無いことの帰結で、学習データを増やしても消えない。
- zenz はもともと辞書変換の候補を検証する部品（azooKey の Zenzai）として作られている。単独の生成器として使う前提ではない。

## 推奨構成（3者一致）

ニューラルモデルの追加学習はしない。zenz の重みは凍結。

```
打鍵列（＋左文脈）
  → 読みラティス: 正規ローマ字の弧（n/nn・si/shi 等の揺れ）
                  ＋ 打鍵ミスの編集弧（QWERTY 隣接置換・脱字・余計な1字・転置。1文2編集・1語1編集まで、コスト付き）
                  ＋ 英語の弧（英単語リスト＋技術語彙リスト。綴り→表記。2文字以下は許可リストのみ）
                  ＋ 数字・記号の弧
  → 辞書ラティスと Viterbi（Mozc dictionary_oss の辞書と接続コスト、BSD-3。辞書に無い区間はひらがな・原文コピーで逃がす）
  → 凍結 zenz で選ぶ（出力は辞書・かな・原文コピーで説明できるものに限る）
  → 選ばれた弧から表記を描画（大文字・空白は英語弧の登録表記から。zenz には出させない）
```

- 英語か日本語かは規則で先に決めず、コストと zenz の比較で決める。
- 安定性の保証: 出力は「入力から、許可した補正と表記変換で説明できるもの」だけ。
- かな漢字の段は入出力を「読み（複数）→ 表層候補＋読みとの対応」に固定し、Python 製と azooKey 製を挿し替えられるようにする。

## 3者で確かめた事実

- 元の zenz-v3.1-small は、読みに英単語を綴りのまま入れると12件すべて綴りのまま出す。ただし大文字・空白は復元しない（github→github、pull request→pullrequest）。句読点の無い読みに句読点を挿入しない。無制約だと読みから外れる（ユウイサ→優位性）。（Claude 実測）
- zenz のトークナイザは空白を落とすので、空白を含む表記はモデルに出させられない。（astra）
- 試験分割358件のうち12件は学習データと完全一致、21件は出力一致。評価から外す。（astra）
- AzooKeyKanaKanjiConverter は公式の動作確認に Windows を含まないが、Package.swift に Windows 分岐があり、Windows＋CUDA の記載もある。読みラティスを注入する公開 API は未確認。MyIME（Windows、Mozc＋azooKey＋Zenzai）は実在するがライセンスは "Other"。（fable・astra・Claude）
- llama-server は `/completion` の `grammar`（GBNF）で制約付き生成ができる。プロンプト側トークンの対数尤度を返す機能は無い（`n_probs` は生成トークンのみ）。（fable・astra）

## 本人が決めること

1. 句読点: (A) `,` `.` `?` `!` は打ち、システムは種類と幅（、。か . ,）だけ決める ／ (B) 打たない句読点の自動挿入を目指す（zenz は挿入しないので別の部品が要り、学習ゼロの方針から外れる可能性）。fable は A を既定に推す。astra は B の可否を独立の小実験で確かめてから決めたい。
2. 英語の表記: 一般語（push、function）は打ったまま小文字、固有名詞・頭字語（GitHub、API）は登録した語だけ表記を変える、でよいか。api→API、python→Python、ok→OK を自動にしたいか。
3. ライセンスの混在: Mozc 辞書（BSD-3）＋ wordfreq（CC BY-SA 4.0）＋ zenz 重み（CC BY-SA 4.0）を同梱して公開してよいか。
