# 常駐入力（このデスクトップで全アプリから使う）

ローマ字の 1 文をそのまま打って Enter を押すと、日本語になって今のアプリに入る。Microsoft IME（MS-IME）は消さずに残す。キー 1 つで、romaji-slm と MS-IME を切り替えられる。方式を選んだ理由は [decisions.md](decisions.md) の D19〜D21 にある。

## 使い方

| キー | 動作 |
|---|---|
| **Ctrl+Alt+Space** | romaji-slm を使う ⇔ 使わない（使わないときは MS-IME がふだんどおり働く）。トレイのアイコンを左クリックしても同じ。使い始めは日本語（トレイのアイコンが **あ**） |
| **Shift+Space** | romaji-slm を使っている間は、日本語 ⇔ 英字を切り替える（MS-IME と同じキー） |
| ローマ字を打つ | 打った文字はアプリに入らず、浮き窓にたまる。打つ手を止めると、変換の 1 位が浮き窓に出る |
| **Enter** | 浮き窓の文をアプリに入れる（変換が済んでいなければ、済みしだい入れる） |
| Space / ↓ / Tab | 候補の一覧を出す。もう一度押すと次の候補（↑ / Shift+Tab で前へ） |
| 候補を出したまま文字を打つ | その候補で確定し、次の文を打ち始める |
| Esc | 候補の一覧を閉じる。もう一度押すと、浮き窓の文を捨てる |
| Backspace | 浮き窓の文を 1 字消す |
| **Shift+Enter** | 打ったローマ字のまま入れる（変換サーバが止まっているときの逃げ道） |

- トレイのアイコン: **あ**（romaji-slm・日本語）、**A**（romaji-slm・英字）、**M**（romaji-slm を使っていない ＝ MS-IME）。
- 浮き窓に溜まるのは、英数字と、US 配列で打てる ASCII の記号すべて（本人の要望 2026-10-16）。変換器が記号を扱う（`(tesuto)` → （テスト）、`[memo]` → 「メモ」、`~kara` → 〜から、`jikan:10ji` → 時間：10時、`50%`・`@`・`#` はそのまま）。
- Ctrl・Alt・Win との組み合わせ（コピー、Alt+Tab など）は浮き窓に文があってもそのまま効く。浮き窓の文は残る。
- 別の欄をクリックしても浮き窓の文は消えない。Enter を押すと、そのとき前面の欄に入る。
- 直前に同じウィンドウへ入れた文の末尾 60 字が、次の変換の左文脈になる。ウィンドウが替わる・矢印キーで動く・5 分あくと、左文脈は空に戻る。
- 句読点を打たなければ、句読点 B で補う。英字は打ったまま（本人の選択、D14）。
- 大文字で打った部分（Shift か Caps Lock）は変換せず、そのまま残る（`sokomadeikutoUInoseiyaku` → そこまでいくとUIの制約、`GPT-4womiru` → GPT-4を見る）。文の途中に略語を挟むとき、Shift+Space で英字に切り替えなくてよい（D34）。

## MS-IME との住み分け

- **romaji-slm を使っていない間**は、キーを 1 つも横取りしない（Ctrl+Alt+Space だけ見ている）。Shift+Space も MS-IME に届く。
- **romaji-slm を使っている間**は、Shift+Space を横取りする。前面の窓に切り替わるたびに MS-IME を閉じる（MS-IME の開閉は窓ごとに持たれるため）。日本語の変換は romaji-slm が担い、MS-IME は英字の素通しになる。
- **切り替えるとき**: 使わないへ切り替えたとき日本語の状態だったら、前面の窓の MS-IME を開く。「日本語を打っている」状態はそのままに、変換の担い手だけを替える。
- 他のアプリが送り込んだキーも、本人の打鍵として扱う（`accept_injected=1`、既定）。この機械では本人の打鍵がすべて送り込まれたキーとして届くため（2026-10-16 の実測で、実際のキー 0・送り込み 239。常駐の Handy などが送り直しているとみられる）。自分が送ったキーは印（dwExtraInfo）で除く。他のアプリが文字キーを送り込んで文字を打つ場合、日本語モードでは浮き窓に入る。Ctrl+V の貼り付けや Unicode での送り込みは、そのまま通る。
- 既知のキーの衝突（2026-10-16 にこの機械の設定を読んで確認）:
  - MS-IME の Shift+Space（IME オン/オフ）。上のとおり、使っている間だけ横取りする。
  - Handy の Ctrl+Shift+Space・Ctrl+Shift+F。使っていない。
  - PowerToys の Keyboard Manager は無効。
  - Ctrl+Alt+Space を使うアプリは、この機械では見つけていない。

## 効かない場所（Windows の制限）

- **管理者権限で動いている窓**には、キーも文字も届かない（UIPI）。その窓では MS-IME を使う。
- 文字を `SendInput` の Unicode で送るので、Unicode の文字入力を受けないアプリ（一部のゲーム、リモートデスクトップの中）には入らない。
- **入力欄でないところ**（本人の報告 2026-10-16: YouTube の k・f などが効かない）: 欄の確認で、文字を打つ欄かも確かめる。入力欄とみなすのは、Win32 のキャレットがある・種類が Edit・値が書き換えられる・文書で TextPattern があり読み取り専用でない、のどれか。入力欄でなければ（Web ページそのもの・動画のプレーヤー・一覧など）、パスワード欄と同じく打鍵をそのまま送り、欄を移すまで素通しにする。UI Automation に応答しないアプリでは分からないので入力欄とみなす。
- **パスワード欄**（UI Automation の IsPassword）: 日本語モードで、今の欄をまだ確かめていなければ、最初のキー（文字に限らず Space・記号・Enter も）から確認が済むまで（0.3 秒で打ち切り）、どの打鍵も解釈せずに預かる。確かめた印は、窓・欄が替わる・モードが替わる・欄を移しうるキー（Tab・Enter・Esc・F キーと、Ctrl・Alt・Win つきのショートカットすべて）がアプリに届く、で消える（フォーカスの通知を出さないアプリでは文が終わるたびにも消える）。パスワード欄の素通しも、欄を移しうるキーで終わる。確認中に欄を移しうるキーを押したら、その後ろに打った文字は（移った先がパスワード欄かもしれないので）捨てる。欄を移しうるキーが確定待ちの列に積まれている間に打った文字は、そのキーを送ってから移った先を確かめるまで預かる（送ってから 0.1 秒待つか、フォーカスの通知が来たら確かめる）。文字キーを押したまま欄を移ったときのリピートも確かめてから扱う。パスワード欄なら預かった打鍵をそのままの順で送り、その欄の間は素通しにする。浮き窓には出さない。普通の欄なら打たれた順に処理し直す。確認中に欄を移ったら、預かった打鍵は捨てる。確かめた欄は覚えておき、2 文目からは待たない。UI Automation に応答しないアプリでは、パスワード欄と分からない。確認にかかる時間は、このデスクトップで初回 135 ms（UI Automation の初期化。起動時に 1 回済ませる）、以後 1〜4 ms（2026-10-16、Windows PowerShell から FocusedElement と IsPassword を 5 回）。
- パスワード欄の見分けで受け入れた限界（Codex のレビュー 11 回の後。decisions.md D23）:
  - フォーカスの通知を出さないアプリで、クリックによって同じ窓の中の欄を移ったことは分からない。低レベルのマウスフックは入れない。
  - 欄を移すキーを押してから 0.1 秒を超えて移るアプリでは、移る前の欄を確かめることがある。
  - パスワード欄の素通しは、欄を移しうるキーか、窓・欄の変化で終わる。
  - 迷ったときは、打った文字を捨てる側に倒す（漏らさない）。そのときは浮き窓に理由が出る。
- 浮き窓の位置は、キャレットを公開しているアプリでは文字の直下に出る。それ以外はフォーカスのある欄の下、どちらも取れなければ前面の窓の下寄りに出る。

## 入れる・外す・更新する

```bash
pwsh -NoProfile -File ime/install.ps1
```

`%LOCALAPPDATA%\romaji-slm\` に入る。

- このとき HEAD のコード、辞書と読みの LM の写し、専用の `.venv` を置く。torch は uv のキャッシュから hardlink される。
- ログオン時の起動（スタートアップのショートカット）と、スタートメニューの「romaji-slm 常駐入力」を作る。
- 新しい版は `app.next\` に組み立てる（HEAD を 1 回だけ読んでその版を写し、その版の `ime/` からトレイアプリをビルドする）。別のポート（`port`+1）で自己試験（`kyouhaiitenki` を打って Enter → 確定文）を通してから、常駐を止めて `app\` と差し替え、起動し直す。自己試験が通らなければ、動いている常駐には触れない。差し替えたあとで失敗したら、前の版（`app.prev\` と `RomajiSlmIme.exe.prev`）に戻して起動し直す。ひとつ前の版は `app.prev\` に残り、次の組み立てで使い回す（`.venv` は差分だけ直す）。
- **更新はふつう自動**: リポジトリから入れたときは、トレイアプリが 1 分ごとにリポジトリの HEAD を見る。`core/` `eval/` `ime/` `pyproject.toml` `uv.lock` が入れた版から変わっていれば、トレイのツールチップに「新しい版あり」と出し、2 段で入れ替える。docs だけのコミットでは入れ替えない。
  1. すぐに `ime/install.ps1 -Stage` を裏で動かす（組み立てと自己試験。打っている間でもよく、今の版はそのまま使える。このデスクトップで約 80 秒）。
  2. 打鍵が `auto_update` 分（既定 3）無く、変換中・確定待ちでもないときに、トレイアプリが `ime/install.ps1 -Swap` を起動して自分から終わる。`-Swap` はその終わりを待ってから差し替え、起動し直す。外から止めないので、打ちかけの文は消えない。
  - 切り替えの間（常駐が終わってから新しいサーバの準備ができるまで、このデスクトップで 5〜75 秒）は日本語が打てない（本人が許容、2026-10-18）。
  - 結果は通知で出る（「新しい版にしました」「新しい版にできませんでした（今の版のまま使えます／前の版で動いています）」）。失敗した版は自動ではもう試さない。記録は `update.log` と `update-result.txt`。
  - 手で入れ替えるときは、トレイのメニューの「新しい版に更新する」（最新でも「押すと入れ直す」）を押す。組み立てと試験が済むと、打鍵の途切れを待たずに切り替わる。上のコマンドをもう一度動かしてもよい（こちらは試験のあと常駐を止めて差し替える）。自動で入れ替えたくなければ `ime.ini` を `auto_update=0` にする。
  - 配布 zip から入れた PC（`source.txt` が無い）では、この確認も自動更新もしない。
- 外すには次のコマンドを使う（`-KeepData` で設定とログを残す）。更新が動いていれば、終わるのを待ってから外す。

```bash
pwsh -NoProfile -File ime/uninstall.ps1
```

- 設定は `%LOCALAPPDATA%\romaji-slm\ime.ini` にある（`device=auto|cuda|cpu`、`port`、前回の on/off）。変えたらトレイの「終了」から起動し直す。
- **実利用の記録**（本人の依頼）: `%LOCALAPPDATA%\romaji-slm\history.jsonl` に 1 行 1 件の JSON で残す。残すのは、確定（`commit`）・Esc で捨てた文（`cancel`）・変換や送信に失敗して浮き窓に戻した文（`restore`）。項目は `time` `event` `romaji`（打った打鍵列） `context`（左文脈） `candidates`（出ていた候補） `chosen`（選んだ番号。1 位なら 0、打鍵列のままなら -1） `text`（入れた文） `raw` `app`（入力先の exe 名） `note`、確定の直後に Backspace で消して打ち直したときは `retype`（`backspaces` 消した字数、`prev_text` `prev_romaji` 直前の確定）。パスワード欄の打鍵は変換せずにそのまま送るので残らない。確定した後にアプリの中で直した結果は見えない。止めるには `ime.ini` を `history=0` にする。30 日を過ぎた行は常駐アプリが消し（起動時と 1 時間ごと）、振り返り済みの行は振り返りの道具が消す（REVIEW.md「消すこと」）。`no_history_apps` に並べたアプリ（既定はパスワード管理のアプリ）は記録しない。
- サーバのログは `server.log`（打った文字列は残さない）。
- 診断: `ime-state.txt`（5 秒ごとの状態。モード・確認待ち・フックの呼ばれた回数と最後に呼ばれてからの時間など）と `ime-debug.log`（モードの変化・欄の確認の結果・フックの付け直し・浮き窓の知らせ）。どちらも打った文字は書かない。
- フックの見張り: キーボードの Raw Input（`RIDEV_INPUTSINK`）にはキーが届いているのに、フックが 1.5 秒呼ばれていなければ、Windows がフックを外したとみなして付け直す（10 秒に 1 回まで）。管理者権限の窓が前面の間も付け直しが起きうるが、害はない。トレイの「使用状況をコピー」で、確定の回数・別候補を選んだ回数・待ち時間の中央値・アプリ別の回数を、貼れる文にして出す。数だけで、文字列は持たない。
- 初めて起動したときは「使っていない」状態で始まる。Ctrl+Alt+Space で使い始める。

## 別の PC（ThinkPad）に入れる（Git で追従。推奨）

本人の決定（2026-10-18）で、ThinkPad はリポジトリを clone して「追従モード」で使う。
常駐アプリが 30 分ごとに GitHub の main から取ってきて（`git fetch` → 早送りの `merge --ff-only`）、今の自動更新（組み立て → 自己試験 → 打っていない間に差し替え）に乗せる。ZIP を作り直して写す手間は要らない。

初回だけ（ThinkPad で、GitHub へのログインは済ませておく）:

1. `git clone https://github.com/morikawa976321/romaji-slm.git`（置き場所は任意）。
2. 開発機で作った配布 zip（`tools/pack-ime.ps1`）を ThinkPad に写す。Git に入れていないモデル（辞書・読みの LM・zenz）を、ここから一度だけ取る。
3. clone したフォルダで `powershell -NoProfile -ExecutionPolicy Bypass -File ime\setup-follower.ps1 -Models <zip のパス>` を実行する。
   - PowerShell 7 と uv が無ければ入れる（PowerShell 7 は winget。管理者の確認が出ることがある）。
   - モデルを写し、`ime.ini` に `pull=main` を書き、組み立て・自己試験・起動まで行う。
   - GPU が無いので torch は CPU 版になる（組み立てのたびに CPU 版の lock を作り直す）。

- 取り込むのは早送りできるときだけで、ThinkPad の clone に手を入れていれば取り込まない（手で触ったものを消さない）。ThinkPad からはコミットしない。
- 取りに行った結果は `ime-debug.log` の `pull:` の行。
- `pull=` を空にすれば取りに行かない（このデスクトップは空。ここのリポジトリは開発用で、複数のセッションが書いているため）。
- 作業途中の版も main に入れば取り込む。入れ替える前の自己試験が関門になる。挙動の変わった版が予告なく入るのが困るなら、評価を通した版だけを指すブランチ（例 `stable`）を作り、`pull=stable` にする。

## 別の PC（ThinkPad）に入れる（ZIP。追従しない）

開発機で配布 zip を作り、その PC で展開して入れる。リポジトリ・git・GPU は要らない。

1. 開発機で `pwsh -NoProfile -File tools/pack-ime.ps1` を実行する。`dist/romaji-slm-ime-<日付>-<hash>.zip`（約 170 MB）ができる。中身は HEAD のコード、辞書と読みの LM、zenz-v3.1-small、CPU 版 torch の uv.lock、ビルド済みのトレイアプリ。
2. zip を ThinkPad に写し、展開する。
3. 展開したフォルダの `install.cmd` をダブルクリックする。`%LOCALAPPDATA%\romaji-slm` に入り、ログオン時の起動を登録して起動する。
   - uv が無ければ公式のインストーラで入れる（ネットワークが要る）。
   - Python と部品の用意は初回だけ数分かかる。
4. 展開したフォルダは消してよい。

- 更新するときは、新しい zip で同じことをする。設定（ime.ini）・記録・ユーザー辞書は、その PC のものが残る。
- 変換は CPU で動く（`device=auto`）。このデスクトップの CPU では 1 文の中央値 552 ms だった。ThinkPad での速さは未測定。
- ユーザー辞書と利用履歴の振り返りは PC ごと。振り返り（ops-daily）はこのデスクトップでだけ動く。ThinkPad の辞書を揃えたいときは、`user_dict.tsv` を写す。
- 試しに別のフォルダへ入れるとき: `powershell -ExecutionPolicy Bypass -File app\ime\install-zip.ps1 -Target <フォルダ> -NoShortcuts -NoLaunch`。`-NoShortcuts` を付けないと、今のショートカットを上書きする。

## 仕組み

```
キー ─ 低レベルキーボードフック（ime/RomajiSlmIme.cs）─ Composer（ime/Composer.cs、状態機械）
                                                         │ 変換の要求（HTTP、127.0.0.1:8767）
                                                         ▼
                                               ime/server.py（CorePipeline.convert_nbest、GPU があれば GPU）
確定 ─ SendInput(KEYEVENTF_UNICODE) で 1 回で送る
```

- フックの中では状態の更新だけをする。通信・描画・MS-IME の開閉は、フックを抜けてから行う。フックの処理が遅いと、Windows が黙ってフックを外すため（LowLevelHooksTimeout）。
- 変換サーバはトレイアプリが起動する。トレイアプリがジョブオブジェクト（KILL_ON_JOB_CLOSE）で抱えるので、トレイアプリが落ちてもサーバは残らない。サーバが落ちたら 3 回まで起動し直す。
- **確定待ちの間の打鍵**: Enter を押してから確定文を実際に送り終えるまで（〜0.3 秒）に、アプリへ渡すはずのキー（2 度目の Enter・矢印・英字・Ctrl+C などの修飾キーつき）が押されることがある。これはその場では渡さずに積み、確定文のあとに同じ順で、1 回の `SendInput` で送る。先に渡すと、チャットで確定文より先に送信が起きる。積んだ修飾キーは OS に届いていないので、修飾キーの状態はフックで自分で追う。
- **失敗したとき**: 応答の待ちは 8 秒で打ち切る。変換の失敗・時間切れ・送信の失敗（`SendInput` の戻り値）のときは、待っていた確定をすべて、打ったローマ字のまま順に浮き窓へ戻す。積んだキーは離鍵だけ送り、押下は捨てる（確定文の無いまま Enter が届かないように）。
- **宛先が変わったとき**: 確定を待っている間に、前面の窓、または同じ窓の中のフォーカスの欄（`EVENT_OBJECT_FOCUS`）が替わることがある。このときは送らずに浮き窓へ戻す。送る直前にも前面の窓を確かめる。
- キーを押しっぱなしにしたときは、押下のときの判断（握りつぶすか渡すか）を、リピートと離鍵まで引き継ぐ。
- ビルドは Windows 同梱の .NET Framework 4.x の csc で行う（.NET SDK は要らない。C# 5）。`pwsh -NoProfile -File ime/build.ps1 [-Test]`。

### 試験

- `pwsh -NoProfile -File ime/build.ps1 -Test`: Composer の状態機械（合成した打鍵で 48 件）。`tests/test_ime_server.py` もこれを呼ぶ。
- `RomajiSlmIme.exe --selftest <打鍵列> <結果ファイル> [--root <app>]`: フックも送り込みも使わずに、本物のサーバで「打鍵 → Enter → 確定文」を通す。本人のキー入力を奪わずに配線を確かめられる。
- 実際のアプリでの打鍵（フックと SendInput、MS-IME の開閉）は、本人の操作でしか確かめられない。
