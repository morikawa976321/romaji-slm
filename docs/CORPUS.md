# 本人の文の材料（語彙の表のため）

本人の決定（docs/decisions.md「本人の方針（2026-11-08…）」「本人の決定（2026-11-08、材料の範囲と誤字脱字）」）:
本人が書いた文を集め、本人がよく使う語彙を調べて、変換でその優先度を少し上げる。モデル（zenz）は追加学習しない（REDESIGN.md）。
集めた文の誤字脱字は AI が直してから数える。

この文書は、材料を集める道具 `tools/corpus.py` と語彙の表を作る道具 `tools/vocab.py` の使い方、誤字脱字を直す AI（直す係）への決まりを兼ねる。

## 置き場所（本人の文と本人のファイルの場所は、リポジトリに入れない）

すべて `%LOCALAPPDATA%\romaji-slm\corpus\` に置く。中身は `tools/corpus.py` の冒頭。
出どころの一覧 `sources.json` も本人のファイルの場所を含むので、ここに置く。

## 出どころの種類

| 種類 | 何を拾うか | 外すもの |
|---|---|---|
| `claude_archive` | ops の archive-transcripts が残す Claude Code の会話の、本人の発言 | 定時ジョブの指示文で始まる会話、アプリの定型文（スキルの本文・要約からの再開・タスクカード・割り込みの印）、貼り付け（`<pasted_content>`）、コード、1,000 字を超える貼り付け文書、フォークで重なった発言 |
| `md_quotes` | md の `>` の引用行（context-engine では本人の原文） | 先の出どころ（会話）に含まれる引用（`dedupe_against_previous`） |
| `files` | .txt・.md・.docx を段落で区切ったもの | `exclude` に当たるパス（配布物・ひな形など）、日本語が 100 字未満のファイル |
| `dialogue` | `**［話し手］**` で区切った対話ログの、指定した話し手の発言 | ほかの話し手 |
| `monocore` | 日次メモ・inbox・予定の題 | AI が一度でも書いた予定の題（`updated_by='agent'`） |

AI が書いた文書（各リポジトリの docs、reports の報告書）は入れない。git の作者名では本人と AI を見分けられない（AI のコミットも本人の名前で入る）ので、出どころはフォルダ・ファイルの単位で本人が決める。
romaji-slm の利用履歴（history.jsonl）も入れない。変換器自身の出力なので、誤変換を本人の語として強めてしまう。

## 手順

1. `uv run python -m tools.corpus collect` — 集め直す。文の id は中身から決まるので、集め直しても済んだ直しはそのまま当たる。
2. `uv run python -m tools.corpus prepare` — まだ直していない文を、約 6,000 字ずつの束にして `fix/in/<束>.jsonl` に書く。
3. 直す係が、束ごとに下の「直しの決まり」で `fix/out/<束>.json` を書く。
4. `uv run python -m tools.corpus apply` — 直しを当てて `clean.jsonl` を作る。直しの `from` が文の中に見つからないときは当てない（当たらなかった数を出す）。直す係が id を隣の文と取り違えたときは、同じ束で `from` を含む文が 1 つだけならその文に当てる。
5. 直しを全部読み（`fix_log.jsonl`）、決まりに反するものを `fix/out/<束>.json` から外すか直して、もう一度 `apply` する。

直す係は、このセッションのサブエージェント（Sonnet）で回した。2026-11-08 の 97 束では直しが 325 個出た。手順 5 で、語を足したり読みの遠い語に替えたりした 4 個を小さい直しに変え、決まりの「直さないもの」の最後の項（「直す先は…」）を書き足した。表記を揃えたように見えた 9 個も一度戻したが、そのうち「〜ずらい」「バックグランド」「まとう」は本人が誤字とした。そこで「直すもの」に加え、直す係が拾わなかった「〜ずらい」も全部直した（`tools/corpus.py` の `add_fixes`）。`claude -p` で回すなら `--no-session-persistence` を付ける（付けないと、渡した本人の文がその会話のログとして保管庫に入り、次に集めるとき本人の発言として拾われる）。

## 語彙の表

`uv run --group data python -m tools.vocab` — `clean.jsonl` を SudachiPy（`data/reading.py` と同じ辞書）で解析し、`vocab.tsv` を書く。

| 列 | 中身 |
|---|---|
| `reading` | ひらがなの読み。表記どおりで、助詞は「は」「を」のまま（打つ綴りと同じ） |
| `surface` | 本人が書いた表記 |
| `pos` | 品詞の上 2 段 |
| `unit` | `AC`: 長い単位（mode C）と短い単位（mode A）で同じ区切りの語。`C`: A に分かれる長い語。`A`: その長い語の中の短い語 |
| `count` / `units` | 出た回数 / 出た文の数 |
| `before` | 2026-10-16（romaji-slm の常駐入力を使い始めた日）より前の回数 |

- 英数字の連続は数えない。数字の直後の語（助数詞）も数えない。SudachiDict は、数字を抜くと助数詞の読みを決められないため。
- 読みの分からない語（辞書に無い漢字の語）は表に入れず、`vocab_unknown.json` に回数だけ書く。
- 2026-11-08 の材料（7,773 件）では、読みと表記の組が 11,430 個、2 回以上出たものが 7,097 個できた。2 回以上の表記が 2 つ以上ある読みは 636 個。読みの分からない語は 4 種だった。
- 2026-10-16 より後にだけ 3 回以上出る漢字の語は 42 個あり、どれも誤変換ではなかった。誤変換を本人の語として強める恐れは、直しのあとでは小さい。
- 表に入る雑音:
  - 本人の造語を SudachiPy が辞書の語に切って、読みの違う語が入る。
  - A の単位では、一字の語（「〜化」の「化」など）が多い。
  - かなのまま残った語（変換し忘れ）も数に入る。
  - 加点では、回数そのものではなく、同じ読みの中での割合と品詞・長さで効かせる。

## 直しの決まり（直す係へ）

入力の束は JSON Lines で、1 行が `{"id", "text"}`。text は本人が書いた文で、キーボード（MS-IME、2026-10-16 以降は romaji-slm を含む）か音声入力（Handy）で入れたもの。
目的は、本人がよく使う語彙を数えること。だから、**明らかな誤りだけを、本人の言葉づかいを変えずに**直す。

直すもの:
- 変換の誤り。同音異義語の取り違え（「資料を買えて」→「資料を変えて」）、区切りの誤りで別の語になったもの。
- 打ち間違い・脱字・余分な字（「しゅっりょく」→「出力」ではなく「しゅつりょく」の打ち間違いなら、本人が書こうとした形に）。
- 音声入力の聞き違い（音が近い別の語になったもの）。
- 英字とかなが混ざって崩れた語（「BESと」→「ベスト」、「gitはぶ」→「GitHub」）。
- 本人が誤字とした書き方（docs/decisions.md「本人の判断（2026-11-08、何が誤字か）」）: 「〜ずらい」→「〜づらい」、カタカナ語の綴りの誤り（「バックグランド」→「バックグラウンド」）、漢字にし忘れてかなのまま残った語（「まとう」→「待とう」）。

直さないもの:
- 表記の揺れ。漢字かかなか（出来る／できる、事／こと）、送り仮名、カタカナ語の長音（サーバ／サーバー）、全角／半角。**本人の選び方こそ数えたいもの**なので、どちらかに揃えない。
- 話し言葉・くだけた言い方・略語・ネットの言い回し・方言・言いさし。
- 句読点の有無と位置、改行、記号。
- 文法がやや崩れていても意味が通るもの。言い換えて読みやすくしない。
- 直す先は、同じ読みの別の書き方か、打ち間違い・聞き違いに近い形に限る。意味を通すために語を足したり、読みの遠い語に替えたりしない。崩れた部分は、残った字を最小限に直すだけにする。
- 英語・コード・パス・URL・コマンド・ファイル名。
- 知らない語（固有名詞・造語・製品名・人名）。正しいとみなす。
- 内容の正しさ（事実の誤り）。

迷ったら直さない。直す係が自信の無い直しを入れるより、誤りが 1 つ残るほうが害が小さい（語彙の表は回数の多い語だけを使う）。

返す形（`fix/out/<束>.json`）:

```json
{"fixes": [{"id": "…", "from": "資料を買えて", "to": "資料を変えて"}], "drop": ["…"]}
```

- `from` は text の中にそのまま含まれる部分文字列。誤りの前後 1〜3 字を含めて、text の中で 1 回しか出ない長さにする。`to` は `from` を直した形。
- 1 つの文に誤りが複数あれば、直しを複数並べる。直すところの無い文は出さない。
- 文として読めないもの（文字化け、打鍵の残骸だけ、意味の取れない断片）は `drop` に id を入れる。
- 文の中身を返事や記録に書き写さない（直しの `from`・`to` に要る分だけ）。
