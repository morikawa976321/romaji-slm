### astra との意見交換と、プロンプト外の検討

### クラウドセッションの活用

本人の指示（2026-10-14）: 「使えるならクラウドセッションもどんどん使って残り230ドルを使い切ってほしい」。クラウドセッションのクレジットは残り約 $230、失効は 2026-11-07。**使い切ることが目的の一つなので、迷ったらクラウドに出す。**

- **立て方**: `claude --cloud "<依頼文>"` を**アプリの Terminal パネル**（`run_in_terminal`）で実行する。TTY が要るので Bash ツールからは動かない。romaji-slm の `tools/cloud-task.ps1` が先例で、依頼文ファイルを渡す形になっている（pwsh 7 で実行）。クラウド側は GitHub の**現在のブランチ**を clone するので、**先に push する**。
- **クレジットの対象**: この方法か、アプリの Cloud 環境で立てたセッションだけ。ルーティン（schedule / RemoteTrigger）は対象外でプランの使用量から引かれるので使わない。Agent ツールの `isolation: "remote"` が対象かは未確認なので、確認できるまで使わない。
- **ネットワーク**: 既定の環境は huggingface.co と download.pytorch.org に届かない。要るなら claude.ai/code の環境設定の Network access を Custom にする。本人の操作が要るならカードに入れる。
- **push の許可**: クラウドに渡すために、**この4リポジトリ（romaji-slm / dotbox / fdm-trunk / lighting-diffuser）に限り、作業ブランチと既定ブランチの push を許可する**（本人の指示による）。context-engine は従来どおり絶対に push しない。クラウドの成果は PR かブランチで受け取り、親がローカルで検証してから既定ブランチに取り込む。
- **向く仕事**: ローカル資源（GPU・Docker・ElegooSlicer・LAN・本人の機器）を要しない、CPU だけで閉じる仕事。CAD 生成、箱詰めや幾何の計算、HTML ページ、テスト、CPU 経路の最適化、文書化、複数案の並列生成、独立レビュー。**向かない仕事**: GPU 評価、Docker と arm64 buildx、スライス（Windows の ElegooSlicer）、LAN 越しの MBP。これらはローカルの親が持つ。
- **並列**: 候補を増やす・別案を同時に作る・同じ問いを別の切り口で解く、といった投機的な並列に積極的に使う。クラウドが返す量が本人の読む量を増やさないよう、親が集約してから出す。
- **依頼文の書き方**: 目的・先に読む文書・書いてよい範囲・終わり方（ブランチ名、何をどこに書いて止まるか）を書く。クラウド側には context-engine も本人のグローバル規則も無いので、必要な本人の基準と禁止事項（要件を変えない、push 先はそのブランチだけ、認証情報を書かない）は依頼文に書き写す。
