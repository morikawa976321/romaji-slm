# 辞書による変換候補（工程3）

`core/kanakanji.py`。読み（`core.types.Reading`）を受け、Mozc の OSS 辞書と接続コストで表記の候補を N-best で返す（`Conversion` のリスト）。[REDESIGN.md](REDESIGN.md) の工程3。

```
uv run --group core python -m core.fetch_mozc          # 辞書を models/mozc/ に取得（コミットしない）
uv run --group core python -m core.kanakanji "キョウハイイテンキデスネ" -n 20 [--words]
uv run --group core python -m eval.kanakanji_check     # 合格条件の測定（AJIMEE 200件）
```

```python
from core.kanakanji import Dictionary, convert
dic = Dictionary.load()            # 起動時に1回（常駐前提）
convs = convert(reading, dic, n=20)
```

## 辞書の形式（Mozc のソースで確認）

- `dictionaryNN.txt`: `読み\tlid\trid\tcost\t表層[\tラベル]`（`src/dictionary/text_dictionary_loader.cc` の `ParseTSV`）。読みはひらがな。読み・表層には `NormalizeVoicedSoundMark`（独立した濁点の合成）がかかる。ここでも同じ処理をしてから、読みをカタカナにして格納する（Reading 側がカタカナのため）。
  - 6列目のラベル: `SPELLING_CORRECTION`（誤った読み。この版で62語）は採らない。`ZIP_CODE`・`ENGLISH` は OSS 辞書に無い。
  - この版は 1,289,076 行。
- `connection_single_column.txt`: 1行目が品詞数 N（この版 2672）、続く N×N 行が接続コスト。i 行目は `rid = i // N`（左の語の右文脈 ID）、`lid = i % N`（右の語の左文脈 ID）（`src/data_manager/gen_connection_data.py`）。`rid = lid = 0` は Mozc が 0 に読み替えるので同じにする。値は 0〜15281。
- `id.def`: `ID 品詞` の連番。0 が `BOS/EOS`。
- コストの尺度は `-log(p) × 500`（`text_dictionary_loader.cc` のコメント）。小さいほどよい。

初回の `Dictionary.load()` は本文から索引を作り `models/mozc/compiled/` に保存する（marisa-trie の索引 19 MB、接続表 14 MB の uint16）。2回目からはそれを開く（索引は mmap）。`VERSION`（取得した版）と書式の版が変わると作り直す。

## ラティスとコスト

Reading の区間を左から並べて1本のラティスにし、文頭（BOS）・文末（EOS）を品詞 0 でつなぐ。

| 区間 | 弧 | 品詞（lid = rid） | 生起コスト |
|---|---|---|---|
| kana | 各位置から、辞書の前方一致で引いた語すべて（`source="dict"`） | 辞書の値 | 辞書の値 |
| kana | 各位置から 1〜16 字の、カタカナのまま・ひらがなのまま（`source="kana"`） | `名詞,一般` | カタカナ 9000+2000×字数、ひらがな 9000+3000×字数 |
| en | `Seg.surfaces`（無ければ `Seg.text`）の1つごとに1弧 | `名詞,一般` | 3000（2番目以降の表記は順位×500 を足す） |
| num | 同上 | `名詞,数,アラビア数字` | 3000（同上） |
| sym | 同上 | 表層で決める: `記号,句点/読点/括弧開/括弧閉/一般`。id.def に表層つきの行（`記号,句点,*,*,*,*,。` など）があればそれ | 1000（同上） |

- 1字のかなの弧を必ず張るので、辞書に無い読みでも行き止まりにならない。
- 語は区間をまたがない。kana の語の `reading` は区間の読みの部分文字列、表層は辞書でその読みに登録された表記か、読みそのもの（カタカナ・ひらがな）だけ。en・num・sym の `reading` は `Seg.text`。
- 探索: 前向き Viterbi（位置ごとに左の語を rid で、右の語を lid でまとめて接続を引く）で各弧の最良前方コストを出し、後ろ向き A* で厳密な N-best を出す。左隣の候補を「前方コスト＋接続」で並べておき、取り出すたびに次の兄弟だけを積む。表記が同じ候補（区切りだけ違う）はコストの小さい1つに畳む。
- `Conversion.cost` は語のコストと接続コスト（BOS・EOS を含む）の和。`Reading.cost` は含まない。
- `Word.lid` / `rid` には接続に使った品詞 ID を入れる（en・num・sym・かなのままの語も。下の「types.py への提案」）。

かなのままの弧のコストは AJIMEE で決めた。1字あたりを 600 / 900（カタカナ / ひらがな）にすると文の大半が1語のカタカナで通ってしまい 1位 27.5%。1500 以上ではほぼ変わらない（1000 / 1500 で 51.0%、1500〜4000 で 53.0%）。基本 5000〜12000 も 52.5〜53.0%。AJIMEE は辞書に載っている語がほとんどで、1位にかなのままの弧が入った項目は 0 件。辞書に無い語（新しい外来語・固有名詞）の扱いはこの評価では決まっていない（未解決の論点）。

## 実測（2026-10-12）

条件: クラウドのコンテナ（Intel Xeon @ 2.10GHz、4 論理コア、15 GB）、Python 3.13.16、marisa-trie 1.4.1、1スレッド。**ThinkPad（Core Ultra 7 255H）の値ではない。デスクトップでも未測定。**

AJIMEE-Bench 200件（`load_ajimee(use_context=False)`）。入力は `meta["kana"]`（正解のカタカナ読み）を `simple_reading` で区間に切ったもの（かなは1区間、記号は1字ずつ sym 区間、表記は記号そのまま）。左文脈は使わない。N=20。

| oracle@20 | **86.0%**（172/200） | 85% 以上 |
| oracle@20（記号・長音を無視） | 86.0% | — |

## 未解決の論点

1. **辞書に無い語の扱い。** 今は「かなのまま」の弧を高いコストで張るだけ。AJIMEE ではこの弧が1位に一度も入らないので、コストは「十分高ければよい」以上に決まっていない。実際には、辞書に無い語は高頻度の付属語の連鎖（ず/ん/だ/もん）で覆われやすく（「ずんだもん」→「ず・ん・だ・もん」で表層は正しいが品詞は誤り）、カタカナ語では途中で辞書の語に割り込まれうる。辞書に無い語の評価セット（新しい外来語・固有名詞・技術語）を工程1の user_style に入れて決めたい。Mozc の未知語処理（文字種で区切る）に近づけるか、zenz にかなのままの候補を常に比べさせるかも候補。
2. **英語・数字・記号の接続コスト。** 英語は `名詞,一般`、数字は `名詞,数,アラビア数字`、記号は句点・読点・括弧の品詞を表層で選び、生起コストは仮の定数（3000 / 3000 / 1000）。区間が強制なので1つの Reading の中では順位に効かないが、工程4で読みの異なる候補（英語区間あり／カタカナ）を `Reading.cost + Conversion.cost` で比べるときに直接効く。Mozc が英語に使う `特殊,短縮よみ`（`ENGLISH` ラベル）は接続表で特殊な扱いなので使っていない。英語を `名詞,固有名詞,一般` とする案、後ろに「する」が続く英語（push する）を `名詞,サ変接続` にする案もある。工程4の評価で決めたい。
3. 数詞の扱い（Mozc の rewriter 相当）。辞書にある「2/ニ」「3/サン」の語で数字の表記が混ざる（「github2push」の候補が3位に出る）。全角・漢数字の揺れは AJIMEE の refs が吸収している。
4. 速度はクラウドの Xeon での値。工程6で ThinkPad で測る。初回だけ索引の構築に 8.7 秒・最大 620 MB かかるので、配布時は compiled/ を作っておくか、初回起動時に作る。

## types.py への提案（変えていない）

- `Word.lid` / `rid` のコメントは「辞書の語以外は -1」だが、接続コストに使った品詞 ID を入れたほうが `Conversion.cost` の内訳が追える。ここではそうしている。コメントを「接続に使った品詞 ID（辞書の語は辞書の値、それ以外は kanakanji が割り当てた値）」に変えたい。
